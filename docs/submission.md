## 3. プロジェクトの説明（497字）

qr-yado（QRやど）は、スマホを使えない高齢者でも自宅や空き家で四国遍路の民泊を開ける仕組みです。宿主は玄関にQRを貼り、紙を受け取るだけ。予約・チェックイン・宿泊者名簿・外国語の案内・帳簿は、外国人宿泊者のスマホとClaudeが引き受けます。
巡礼者は旅の始まりに1回登録し、巡礼カードから道中の宿を予約します（2泊目以降は前々日の正午から）。宿に着いてQRを読むと、Claudeが旅券を読み取り、カタカナの読みと日本語に訳したひとことを添えた紙が1人1泊1枚、数秒で印刷されます。宿主は現金を受け取って署名するだけ。その紙が宿泊台帳の原本です。
窓口（商工会など）は要員の○×を入れるだけで当番と日当が決まり、宿の案内は日本語で書けばClaudeが7言語に訳します。月の帳簿はfreee会計に取り込め（実アカウントで検証済み）、四国全体の需給ボードで詰まる区間を先に知り、公民館への依頼文をClaudeが下書きします。
Claudeは読み取り・翻訳・下書きに限り、金額や180日上限の計算はテスト付きのコード。仕様の言語化から本番確認まで、チャットの裏でClaude Codeが書きました。

## 6. Claude Code での開発の感想

今回いちばん変わったのは「作り方」でした。Claude のチャットで仕様を言葉にしていくと、同じ会話の裏で Claude Code がコードを書いて GitHub に push し、Cloudflare に自動でデプロイされる。私はターミナルを開いていません。11/2 から 11/8 までの 42 コミットはすべてこの形で、各コミットにチャットのセッションへのリンクが入っています。

良かったこと：
- 仕様の議論 → Claude Design で主要画面の案を確認 → 実装 → 本番の通し（Claude が私の Chrome を操作して予約からチェックイン、紙の印刷まで）→ freee への取り込み検証、までが一つの流れで進んだ。手数が少ない
- 本番で出た問題（freee の勘定科目名の違い、管理番号の20文字制限、iPhone の写真形式、QR を読むと言語が切り替わる）を、その場で直して数分で本番に反映できた。決定事項は docs/decisions.md に D-01〜D-30 として残り、仕様の正本になった
- 法令の義務（宿泊者名簿、外国語の案内、定期報告、180日）を表にして、どのコードとテストが満たすかを紐づけられた

気をつけたこと：
- Claude に任せるのは読み取り・分類・翻訳・下書きまで。金額・日数・当番・上限判定は普通のコードでテストを書いた。Claude の出力は JSON で返させて検証してから使う
- Claude API は「変わったときだけ」呼ぶ設計にした（宿の案内の翻訳は文面が変わったときだけ、旅券の読み取りは1人1回）。デモでは派手に見えるが、運用で費用と待ち時間を増やさないため

学んだこと：
- 途中で Claude が根拠の薄い懸念を断定口調で並べ、私の意欲が一度折れかけた。根拠を問い、撤回させ、「事業化のときに確認すること」として切り分けた。AI と組むときは、反論の根拠を確かめる役が人間側に要る
- 1人で1週間、仕様から本番まで届いたのは、話した言葉がそのまま設計書とコードになったから。次は実際に宿を1軒開けて、紙が人と人の会話を生むかを確かめたい
